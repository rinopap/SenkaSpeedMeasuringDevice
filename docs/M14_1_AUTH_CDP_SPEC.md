## 1. 本仕様書の目的

M13認証・CDP追補調査において、現行のCDP付きブラウザ起動方式がGoogle認証との互換性に問題を生じさせる可能性が確認された。

戦果時速計測機はゲームの認証情報を必要とするソフトウェアではなく、ブラウザが受信済みの累積経験値を読み取る専用計測器である。

したがって、認証処理と通信観測処理を可能な限り独立させる。

利用者が通常のブラウザ環境で認証し、その後、利用者の明示的な意思およびブラウザ側の正規の接続許可に基づいて計測を開始する構造を目指す。

本仕様書は既存の次期開発統合仕様書に対する追加・変更仕様書とする。

既存の通信非仲介性、非改変性、ローカル完結性、セキュリティ要件を緩和しない。

## 2. 現在の確認状況

### 2.1 確認済み事項

M13認証・CDP追補報告書に基づき、以下を確認済みとする。

- ChromeおよびEdgeのCDP計測について利用者による動作報告がある。
- CDP付きChromeおよびEdgeにおいてGoogle認証警告が発生したとの利用者報告がある。
- EdgeでCDPを使用しない状態で認証した後、同一専用プロファイルを利用したCDP計測が成立したとの利用者報告がある。
- 現行CDP取得ポリシーは正規ゲームURLおよび選択された所属サーバーを検証する。
- 認証ページ等へ遷移した場合は対象API本文の取得許可を無効化する。
- 認証ページのデータを抽出・保存・転送する処理は報告書の調査範囲では確認されていない。

### 2.2 未確認事項

- Google認証警告の直接的な判定条件。
- Edgeにおけるブラウザ公開属性の実際の値。
- Chrome 144以降の承認型CDPへの独自C#クライアントによる接続。
- 承認型CDPの権限範囲および切断後の失効動作。
- Vivaldi、Brave、Operaの認証互換性。
- 74EN内蔵WebView2の認証互換性。
- 艦これ運営によるCDP利用の規約上の取り扱い。

Chromeの技術仕様を他のChromium系ブラウザにも無条件に適用できるとは判断しない。

### 2.3 ビルド・試験状況

報告書に記載された試験結果：

- 認証ページ除外に関する対象試験：3件成功。
- 全自動テスト：83件成功、2件失敗。
- WPF Releaseビルド：未完了。

失敗した試験はHttpListener fixtureおよび待受プロセス照合に関するものであり、報告書では開発環境の制限が原因とされている。

ただし、正常な開発環境で再実行するまでは成功扱いしない。

## 3. 最上位設計原則

以下を必須とする。

- ゲーム通信を仲介しない。
- ゲーム通信を改変しない。
- ゲームAPIを独自送信しない。
- ゲーム操作および認証操作を自動化しない。
- 認証情報を取得、解析、保存、転送しない。
- ゲームページへJavaScriptを注入しない。
- Fetchインターセプトを使用しない。
- 認証サービスのセキュリティ機能を変更しない。
- 運営側の検知回避を行わない。
- ブラウザの公開属性を偽装しない。
- 計測機自身が外部通信を行わない。
- 計測機の終了によってブラウザを終了させない。
- ブラウザ拡張機能、独自プロキシ、独自証明書を必須としない。

認証互換性や操作性を改善するために、上記の要件を緩和してはならない。

## 4. 接続方式の区分

接続方式を以下のように区分する。

### 4.1 通常認証モード

利用者が通常のブラウザ環境で認証するためのモード。

本ソフトは認証通信を観測しない。

認証のためにCDP接続を行わない。

Google、DMM等の認証ページに対して特別なデータ取得処理を設けない。

### 4.2 従来型CDP計測モード

既存のCDP通信取得機能を使用する。

ブラウザの起動設定によりCDPが有効になること、外部デバッグ権限が存在することを利用者に明示する。

認証ページの監視停止と、ブラウザ自体のデバッグ設定の解除が異なることを説明する。

### 4.3 利用者承認型CDP計測モード

ブラウザが公式に提供する、起動済みブラウザへの承認型デバッグ接続を利用する方式。

通常起動したブラウザを再起動せず、利用者の明示的承認により計測を開始できる構成を目標とする。

現段階では研究・検証対象であり、正式採用済みとして扱わない。

### 4.4 74EN JSON監視モード

既存機能を維持する。

本方式では計測機によるCDP有効化を必要としない。

ただし、74EN自体の利用規約上の位置付けを保証するものではない。

## 5. 認証完了の判定方式

### 5.1 基本方針

認証完了を確認するために、認証情報へアクセスしてはならない。

以下の方法は採用しない。

- Cookieデータベースの読み取り。
- ブラウザのログイン情報の読み取り。
- 認証トークンの取得。
- GoogleまたはDMMへの独自認証確認リクエスト。
- ページへのJavaScript注入。
- ブラウザメモリの解析。
- ログイン状態確認のための認証通信の監視。

### 5.2 利用者による完了確認

初回認証および再認証時には、利用者自身が認証完了を確認する。

利用者が計測開始ボタンを押したことを計測開始要求として扱う。

この操作は認証サービスによる認証完了の証明ではない。

### 5.3 計測可能性の確認

接続が許可された後、以下の条件によって計測可能性を確認する。

- 正規ゲームページであること。
- 有効な対象フレームであること。
- 選択された所属サーバーと一致すること。
- 対象APIパスと一致すること。
- 正常なレスポンスであること。
- 有効な監視セッションに属すること。
- 必要な経験値情報が正常に解析できること。

正常な母港APIの観測をもって計測中と表示する。

APIを受信するまでの状態は、認証失敗ではなく対象API待機中として扱う。

確認目的のゲームAPI送信やページ再読み込みを行わない。

## 6. ログイン準備機能

### 6.1 目的

利用者が計測処理とは独立した環境で通常の認証操作を行えるようにする。

### 6.2 起動条件

利用者の明示操作によって通常認証モードを利用できるようにする。

ブラウザの通常の認証機能を利用する。

独自の認証画面、認証フォーム、認証情報入力欄は作成しない。

### 6.3 認証情報の管理

認証状態の保存および管理はブラウザ自身に任せる。

本ソフトがCookie、セッション情報、認証トークンを読み取り、複製、移植、編集してはならない。

日常利用プロファイルから計測用プロファイルへの認証情報の移送は行わない。

専用プロファイル内の認証情報も、CDPが有効な状態では高権限アクセスのリスクがあることを説明する。

### 6.4 認証拒否時の取り扱い

Google、DMM等のサービスが認証を拒否した場合は、その制限を尊重する。

認証エラー時に以下を行わない。

- User-Agent変更。
- navigator.webdriverの書き換え。
- 認証判定に関係するブラウザ属性の偽装。
- 認証制限回避を目的とした起動引数変更。
- 認証情報の抽出および移植。
- 認証リクエストの改変や再送。
- 無断での別接続方式への切り替え。

利用者には認証互換性の問題を案内し、計測を保留できるようにする。

## 7. 承認型CDPの技術検証

### 7.1 調査対象

Chrome 144以降の公式な利用者承認型リモートデバッグ機能を対象とする。

以下の公式資料を参照する。

https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session

https://developer.chrome.com/docs/devtools/agents/get-started/configuration/

### 7.2 検証項目

- 通常起動済みChromeでの利用可能性。
- C#クライアント単体による正式な接続可否。
- 利用者による接続承認および拒否。
- 承認の有効期間。
- 承認範囲。
- 接続解除後のデバッグ権限。
- ブラウザUIからの承認取り消し。
- 他のローカルクライアントとの同時接続。
- 対象ページの限定。
- 複数タブにおけるプライバシー保護。
- iframeおよびOOPIFの互換性。
- 既存CdpCommandPolicyとの統合。
- 計測機の異常終了時のゲーム通信継続。
- ブラウザ再起動の要否。

### 7.3 試験環境

実際のGoogleアカウントやDMMアカウントを必要としないローカル合成環境で技術検証する。

模擬ゲームページ、模擬認証ページ、模擬APIを用いて確認する。

公式な利用者承認を省略または回避する接続手段を実装しない。

### 7.4 追加依存関係

Chrome DevTools MCPやNode.js等の追加ランタイムを一般利用者への必須条件としない。

独自C#クライアントによる安全な直接接続が成立しない場合は、承認型CDPの正式採用を保留する。

### 7.5 採用条件

以下をすべて満たした場合に採用候補とする。

- ブラウザの正規機能を利用している。
- 利用者の明示的な接続承認がある。
- 認証ページを観測しない。
- 既存のCDPコマンド制限が維持される。
- 外部ネットワーク通信を追加しない。
- ブラウザのセキュリティ機能を変更しない。
- ブラウザと計測機の障害独立性が維持される。
- 残存するデバッグ権限リスクが明確になっている。

## 8. ブラウザ再起動を伴う方式の評価

M13追補報告書に記載された通常認証と従来型CDP計測の分離方式について、安全性、認証互換性、操作性を評価する。

専用プロファイルにおける通常認証モードと計測モードは、明確に区別する。

以下を遵守する。

- ブラウザの強制終了を行わない。
- 利用者の同意なくブラウザを再起動しない。
- 認証状態を計測機が読み取らない。
- 認証情報を別プロファイルへ移送しない。
- 他のブラウザウィンドウや日常利用環境に影響させない。
- 認証サービスの制限を尊重する。
- ゲーム運営側からの検知不能性を保証しない。

ブラウザ再起動方式を認証制限の回避手段として提供してはならない。

正式採用の可否は安全性およびサービス利用条件を含めて開発者が判断する。

## 9. 監視状態の管理

認証状態と通信取得状態を混同しない。

以下の状態を管理する。

| 状態 | 意味 |
|---|---|
| Disabled | 計測機能無効 |
| AuthenticationPreparation | 通常認証準備中 |
| WaitingForUser | 利用者の操作待ち |
| WaitingForConsent | ブラウザ側の接続承認待ち |
| Connecting | 許可された接続処理中 |
| WaitingForGamePage | 正規ゲームページ待ち |
| WaitingForApi | 正常な母港API待ち |
| Capturing | 計測中 |
| Suspended | 対象外ページ等により取得停止 |
| ConnectionError | 接続エラー |
| Unsupported | 接続方式未対応 |

状態名は実装候補である。

既存の監視状態管理と重複する仕組みを不必要に作らない。

計測可能性を確認できていない状態で「計測中」と表示しない。

## 10. 認証ページへの遷移

ゲームプレイ中に再認証やログインページへの遷移が発生した場合、現行のセキュリティポリシーを適用する。

- 現在の監視世代を無効化する。
- 保留中の本文取得許可を破棄する。
- 対象外ページのNetwork監視を停止する。
- 認証ページの本文を取得しない。
- 不要な子セッションを維持しない。
- 必要に応じてCDP接続を終了する。
- 利用者に再認証が必要であることを案内する。

ページ遷移やログイン操作そのものを妨げない。

従来型CDPでは接続解除後もブラウザ側のデバッグ設定が残る可能性を明示する。

認証ページへ遷移したことだけを根拠に、認証情報の有効性を確定しない。

## 15. ビルド・自動テストの再確認

M13追補報告書で失敗した2件の試験について、正常なWindows開発環境で再実行する。

確認対象：

1. HttpListenerを使用したCDP合成試験。
2. CDP待受プロセスの照合試験。
3. WPF Releaseビルド。
4. 既存の全自動テスト。

実行環境の制約に起因する失敗と、製品実装の不具合による失敗を区別する。

環境制約を理由にテスト自体を削除したり、無条件で成功する試験に変更したりしない。

## 16. 追加試験

### 16.1 通常認証モード

ローカル合成ページを用いて確認する。

- 認証準備中にCDPによる通信観測を開始しない。
- 認証準備中に認証情報を取得しない。
- ログイン完了操作なしで監視を自動開始しない。
- 所属サーバー未選択時に計測を開始しない。
- 認証エラー時に計測が停止状態を維持する。

### 16.2 承認型接続

- 接続承認による正常な開始。
- 接続拒否時の計測停止。
- 承認取り消し時の接続終了。
- 切断時の監視世代無効化。
- 対象外ページの本文取得拒否。
- 他タブの本文取得拒否。
- 計測機の正常終了。
- 計測機の強制終了。
- ブラウザ終了後の安全な状態復帰。

### 16.3 状態管理

- 認証準備から接続待機への移行。
- 接続待機からAPI待機への移行。
- 正常な母港API受信後の計測開始。
- 対象外ページ遷移時の監視停止。
- 古い監視セッションの破棄。
- 再認証時の状態移行。
- 取得方式切り替え時の二重計測防止。

### 16.4 通信非干渉性

既存仕様に従い、以下を検証する。

- 計測機によるAPI追加送信がない。
- レスポンス本文を変更しない。
- 通信を停止、保留、再送しない。
- 認証操作を自動化しない。
- 計測機の停止がブラウザ通信に波及しない。
- 計測機自身による外部通信がない。

## 17. 利用規約および警告への対応

CDP方式が技術的に利用可能であることと、ゲーム運営がその利用を許可していることを区別する。

公開されている利用規約および運営告知に基づき、規約上の位置付けを整理する。

運営への問い合わせを今回の実装工程の必須条件とはしない。

ただし、問い合わせを行わないことを許可の根拠としない。

次の行為を実施しない。

- 運営の検知回避機能の追加。
- ブラウザの公開属性の偽装。
- 認証サービスの制限回避。
- アカウント停止を利用した検知限界の探索。
- 停止措置や警告後の利用制限回避。

アカウント停止や認証警告等は安全性評価上の問題として記録し、該当する試験を中止する。

処分されなかったことを規約適合性の証明として使用しない。

正式公開の判断は技術的安全性、認証互換性、規約上の不確実性を個別に評価した上で行う。

## 18. 利用者向け説明

以下の内容をREADMEまたは設定画面で説明する。

- 計測機は認証情報を取り扱わない。
- ログイン操作は利用者自身が行う。
- ブラウザによって接続方式が異なる。
- CDPには強いデバッグ権限がある。
- 計測機終了後もブラウザのデバッグ設定が残る場合がある。
- 一部の認証サービスと互換性がない場合がある。
- 計測機がゲーム通信を改変しないことは、利用規約上の許可を意味しない。
- 運営側からの検知不能性を保証しない。
- 未確認のブラウザを正式対応済みとしない。
